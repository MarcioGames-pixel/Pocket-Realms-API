# Pocket Realms API (community prototype)

A Node.js REST API prototype for researching the HTTP endpoints found in the Minecraft: Pocket Edition 0.7.0 client. This is an independent community project and is not affiliated with or endorsed by Mojang or Microsoft.

## Status

**Early prototype — not yet confirmed wire-compatible with the original client.** Endpoint paths were found in the 0.7.0 native library, but the exact request methods, parameter encoding, response schemas, authentication semantics, and error formats still need verification against the client. Responses in this repository are an initial documented design, not a claim of complete compatibility.

This is an HTTP metadata/session prototype only. It does **not** implement RakNet, a Minecraft world, chunk/entity packets, or a playable multiplayer server. A Realm appearing in the API list does not mean a game server is running.

## Requirements

- Node.js 18 or newer
- No third-party runtime dependencies

## Web dashboard

Open `http://127.0.0.1:42480/` after starting the server to use the mobile-friendly HTML panel. The panel creates a **local demo session** through `POST /m/session`, displays API status and open realm records, and lets you create/open/close metadata records. It does not authenticate with Mojang/Microsoft and must not be given real passwords, refresh tokens, or account secrets. Session tokens are not currently enforced as authorization for the other API routes, so keep this prototype on a trusted network only.

## Run

```sh
npm start
```

By default the API listens on `0.0.0.0:42480`. Set `PORT`, `HOST`, and optionally `DATA_DIR` to configure it. JSON data is stored in `data/store.json`; do not put this directory in a public repository.

Health check:

```sh
curl http://127.0.0.1:42480/health
```

Run tests:

```sh
npm test
```

## Implemented prototype routes

All responses are JSON unless noted. IDs are generated by this prototype.

| Route | Methods | Current behavior |
| --- | --- | --- |
| `/`, `/index.html`, `/app.js`, `/style.css` | GET | Local web dashboard assets |\n| `/health` | GET | Process health |
| `/info/status` | GET | API status and counts |
| `/server/list` | GET | Lists open metadata records |
| `/server/create?name=NAME&type=survival&seed=0` | GET, POST | Creates a realm metadata record |
| `/server/:id/open` | GET | Marks record open |
| `/server/:id/close` | GET | Marks record closed |
| `/server/:id/name?name=NAME` | GET, POST | Renames a record |
| `/server/:id/whitelist?player=NAME` | GET, POST | GET adds a name; POST uses `{"action":"add","player":"NAME"}` or `{"action":"remove","player":"NAME"}` |
| `/server/:id/join?username=NAME` | GET, POST | Prototype join metadata/session response; no game connection |
| `/server/heartbeat?nplayers=0&id=1` | GET, POST | Updates the player count for a record |
| `/m/session?username=NAME` | GET, POST | Creates a local demo session |
| `/m/session/logout?sessionId=TOKEN` | GET, POST | Revokes a local demo session |
| `/auth/validate-player/NAME/TOKEN` | GET | Validates a token created by this API |

The API accepts some query/body alternatives for convenient testing. That flexibility is not proof that the original 0.7.0 client sends the same requests.

## Compatibility research checklist

- [ ] Inspect the client call sites and determine exact HTTP verbs, query escaping, headers, and bodies.
- [ ] Record successful and failed response examples from the original service/client where legally and safely available.
- [ ] Match JSON or text response shapes and HTTP status behavior.
- [ ] Verify session lifecycle, invite checks, owner permissions, and heartbeat semantics.
- [ ] Add captured, sanitized fixtures and regression tests.
- [ ] Implement a separate compatible RakNet/game-server component before claiming playable multiplayer.

Do not use real Microsoft/Mojang passwords, refresh tokens, or other account secrets with this prototype. Session tokens here are local demonstration tokens, not official credentials. Do not expose this early prototype publicly without adding authentication/authorization, rate limits, HTTPS at the deployment edge, and operational safeguards.

## Endpoint evidence

The route strings documented above were found in the Minecraft PE 0.7.0 native library, including `/server/list`, `/server/%lld/join`, `/server/%lld/close`, `/server/%lld/open`, `/info/status`, `/m/session/logout`, `/server/heartbeat?nplayers=%d`, `/m/session`, `/auth/validate-player/%s/%s`, and `/server/create?name=%s&type=%s&seed=%d`. The strings alone do not establish the full protocol.
